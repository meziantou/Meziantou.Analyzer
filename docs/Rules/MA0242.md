# MA0242 - Use a value factory to compute the value only when the key is not in the ConcurrentDictionary

## Description

`ConcurrentDictionary<TKey, TValue>.GetOrAdd(key, value)` and `ConcurrentDictionary<TKey, TValue>.AddOrUpdate(key, addValue, updateValueFactory)` evaluate the value before the call, even when the key is already in the dictionary and the value is not used. When computing the value is expensive, use the overloads that take a `Func<TKey, TValue>`, so the value is only computed when the key is not in the dictionary.

The rule reports the values that are not cheap to evaluate, such as method calls, object creations, collection expressions, string concatenations, interpolated strings, indexers, or `await` expressions. It does not report the constants, the variables, the fields, the properties, the casts, and the built-in operators applied to such values.

````c#
using System;
using System.Collections.Concurrent;
using System.Collections.Generic;

var dict = new ConcurrentDictionary<string, int>();
var value = 27;
dict.GetOrAdd("1", value); // ok
dict.GetOrAdd("2", (int)Math.Ceiling(Math.Pow(value, 2))); // report diagnostic
dict.GetOrAdd("2", _ => (int)Math.Ceiling(Math.Pow(value, 2))); // ok

var lists = new ConcurrentDictionary<string, List<int>>();
lists.GetOrAdd("key", new List<int>()); // report diagnostic
lists.GetOrAdd("key", _ => new List<int>()); // ok
````

## How to fix violations

Use a lambda to compute the value. If the lambda captures variables, you can then use the overload with the `factoryArgument` parameter to avoid the closure ([MA0106](MA0106.md)):

````c#
dict.GetOrAdd(key, _ => obj.ToString());
dict.GetOrAdd(key, (_, arg) => arg.ToString(), obj);
````

Note that the value factory is not evaluated when the key is already in the dictionary. If the evaluation of the value has side effects that must always occur, suppress the diagnostic.
