# MA0031 - Optimize Enumerable.Count() usage
<!-- sources -->
Sources: [OptimizeLinqUsageAnalyzer.cs](https://github.com/meziantou/Meziantou.Analyzer/blob/main/src/Meziantou.Analyzer/Rules/OptimizeLinqUsageAnalyzer.cs), [OptimizeLinqUsageFixer.cs](https://github.com/meziantou/Meziantou.Analyzer/blob/main/src/Meziantou.Analyzer.CodeFixers/Rules/OptimizeLinqUsageFixer.cs)
<!-- sources -->

Replace `Count()` with a more optimized method.

```csharp
enumerable.Count() > 10;

// Should be
enumerable.Skip(10).Any();
```

When the value is not a constant, it may be negative or 0, so `Skip(n).Any()` is not equivalent to the comparison: `Count() >= n` is `true` when `n` is 0, whereas `Skip(n - 1).Any()` is `false` for an empty sequence. In this case, the rule suggests using `Take` to stop enumerating the sequence as soon as the result is known.

```csharp
enumerable.Count() >= n;
enumerable.Count() > n;

// Should be
enumerable.Take(n).Count() >= n;
enumerable.Take(n + 1).Count() > n;
```
