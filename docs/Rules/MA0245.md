# MA0245 - Review the conversion of a floating-point value to decimal

Source: [FloatingPointToDecimalConversionAnalyzer.cs](https://github.com/meziantou/Meziantou.Analyzer/blob/main/src/Meziantou.Analyzer/Rules/FloatingPointToDecimalConversionAnalyzer.cs)

## Description

.NET 11 changed how `float` and `double` values are converted to `decimal`. Previous versions rounded the value to 7 (`float`) or 15 (`double`) significant digits, while .NET 11 converts the exact binary value. So, the same code returns a different value when it runs on .NET 11:

````c#
double value = 2.3;
var result = ((decimal)value).ToString(CultureInfo.InvariantCulture);
// .NET 10 and previous versions: 2.3
// .NET 11:                       2.2999999999999998223643160600
````

See the [breaking change documentation](https://learn.microsoft.com/en-us/dotnet/core/compatibility/core-libraries/11/decimal-biginteger-floating-point-conversions) for more information.

The rule reports the conversions of a non-constant `float` or `double` value to `decimal`, so that you can review the code whose result changed:

- Explicit casts to `decimal` or `decimal?`
- `new decimal(double)` and `new decimal(float)`
- `Convert.ToDecimal(double)` and `Convert.ToDecimal(float)`
- `decimal.CreateChecked`, `decimal.CreateSaturating`, and `decimal.CreateTruncating`

The conversions of constant values are reported by [MA0244](MA0244.md).

The rule is disabled by default. You can enable it using an `.editorconfig` file:

````editorconfig
[*.cs]
dotnet_diagnostic.MA0245.severity = suggestion
````

````c#
void Sample(double value)
{
    decimal a = (decimal)value;             // non-compliant
    decimal b = new decimal(value);         // non-compliant
    decimal c = Convert.ToDecimal(value);   // non-compliant
}
````

## How to fix violations

There is no code fix, as the correct replacement depends on the intent. Keep the conversion if the exact value is expected, or round the value to the number of significant digits that the previous versions of .NET used, as described in the breaking change documentation. You can then suppress the diagnostic.
