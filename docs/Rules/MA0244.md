# MA0244 - Use a decimal literal instead of converting a floating-point constant to decimal

## Description

.NET 11 changed how `float` and `double` values are converted to `decimal`. Previous versions rounded the value to 7 (`float`) or 15 (`double`) significant digits, which hid the fact that a binary floating-point literal is not the same value as the decimal literal with the same text. .NET 11 converts the exact binary value instead:

````c#
var result = ((decimal)2.3).ToString(CultureInfo.InvariantCulture);
// .NET 10 and previous versions: 2.3
// .NET 11:                       2.2999999999999998223643160600
````

When the conversion is a constant, the compiler of the .NET 11 SDK computes the value at compile time and embeds it into the assembly, whatever the target framework. So, rebuilding a `netstandard2.0` or `net8.0` library with the .NET 11 SDK is enough to change its behavior. See the [breaking change documentation](https://learn.microsoft.com/en-us/dotnet/core/compatibility/core-libraries/11/decimal-biginteger-floating-point-conversions) for more information.

The rule reports the conversions of a constant `float` or `double` value to `decimal`:

- Explicit casts to `decimal` or `decimal?`
- `new decimal(double)` and `new decimal(float)`
- `Convert.ToDecimal(double)` and `Convert.ToDecimal(float)`
- `decimal.CreateChecked`, `decimal.CreateSaturating`, and `decimal.CreateTruncating`

````c#
decimal a = (decimal)2.3;               // non-compliant
decimal b = (decimal)14.1f;             // non-compliant
decimal c = new decimal(123.4567);      // non-compliant
decimal d = Convert.ToDecimal(0.1);     // non-compliant
decimal e = decimal.CreateChecked(2.3); // non-compliant

const double Rate = 0.23;
decimal f = (decimal)Rate;              // non-compliant

decimal g = 2.3m;                       // compliant
````

The rule also reports the non-integer values of the test data attributes (xUnit `[InlineData]`, NUnit `[TestCase]`, MSTest `[DataRow]`, and the attributes deriving from them) when the corresponding parameter of the test method is a `decimal`. C# does not allow `decimal` values in attributes, so these values are `double` or `float` constants that the test framework converts to `decimal` at runtime:

````c#
[Theory]
[InlineData(2.3)]   // non-compliant
[InlineData("2.3")] // compliant
public void Test(decimal value) { }
````

## How to fix violations

Use a decimal literal. The code fix replaces the conversion of a numeric literal, optionally preceded by a unary minus, with a decimal literal built from the original text (`(decimal)1e-3` becomes `1e-3m`, `(decimal)1_000.5` becomes `1_000.5m`). There is no code fix for the other constant expressions, such as a constant field or a computed value.

Note that a decimal literal keeps the trailing zeros, so `(decimal)2.50` and `2.50m` are equal, but are not formatted the same way (`2.5` and `2.50`).

For the test data attributes, pass the value as a string or use a member data source (xUnit `[MemberData]`, NUnit `[TestCaseSource]`, MSTest `[DynamicData]`). There is no code fix.

To audit the non-constant conversions, whose result also changed in .NET 11, enable [MA0245](MA0245.md).
