# MA0243 - Use an escape sequence for invisible characters

## Description

Invisible characters and special spaces written directly in a string or a character literal cannot be distinguished from regular spaces, or are not visible at all, when reading or reviewing the code. For instance, `"a b"` may contain a no-break space instead of a space, and a bidirectional control character can make the code look different from what the compiler sees. Use an escape sequence to make these characters explicit.

The rule reports the following characters in string literals (including verbatim, raw, interpolated, and UTF-8 strings) and character literals:

- Control characters: U+0000 to U+001F (including the tab character), U+007F, and U+0080 to U+009F. The carriage return and line feed characters are not reported (see [MA0101](MA0101.md))
- Special spaces: U+00A0 (no-break space), U+1680, U+2000 to U+200A, U+202F (narrow no-break space), U+205F, U+3000
- Zero-width and format characters: U+00AD (soft hyphen), U+034F, U+115F, U+1160, U+17B4, U+17B5, U+180E, U+200B (zero width space), U+200C (zero width non-joiner), U+2060 to U+2064, U+206A to U+206F, U+2800 (braille pattern blank), U+3164, U+FEFF (zero width no-break space / BOM), U+FFA0, U+FFF9 to U+FFFB, U+1BCA0 to U+1BCA3, U+1D173 to U+1D17A, U+E0001
- Bidirectional control characters: U+061C, U+200E, U+200F, U+202A to U+202E, U+2066 to U+2069
- Line and paragraph separators: U+2028, U+2029

The characters used by emoji sequences are not reported: the zero width joiner (U+200D), the variation selectors (U+FE00 to U+FE0F, U+E0100 to U+E01EF), and the tag characters (U+E0020 to U+E007F).

The rule is disabled by default. You can enable it using an `.editorconfig` file:

````editorconfig
[*.cs]
dotnet_diagnostic.MA0243.severity = suggestion
````

````c#
_ = "a b";      // non-compliant: the literal contains a no-break space (U+00A0)
_ = "a\u00A0b"; // compliant

_ = '	';        // non-compliant: the literal contains a tab
_ = '\t';       // compliant
````

## How to fix violations

Replace the character with an escape sequence: `\t`, `\0`, `\a`, `\b`, `\f`, `\v`, `\e` (C# 13 or later), `\uXXXX`, or `\UXXXXXXXX` for the characters outside the Basic Multilingual Plane.

The code fix replaces the characters of the literal with escape sequences. As verbatim strings do not support escape sequences, the code fix converts them to regular strings:

````c#
_ = @"C:\temp a";  // non-compliant: the literal contains a no-break space (U+00A0)
_ = "C:\\temp\u00A0a"; // compliant
````

Raw string literals do not support escape sequences, so there is no code fix for them.
