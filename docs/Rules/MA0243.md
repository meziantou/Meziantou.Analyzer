## Description

Non-ASCII characters in source files can be hard to read, can be confused with ASCII characters, can be lost when a file is saved with the wrong encoding, and can hide code from reviewers: zero-width characters, non-breaking spaces, and bidirectional control characters are invisible in most editors. This rule reports the characters that are not printable ASCII characters, wherever they are in the file: string and character literals, comments, documentation comments, identifiers, whitespace, preprocessor directives, and disabled code.

The rule is disabled by default. The printable ASCII characters (`U+0020` to `U+007E`), the tab, the carriage return, and the line feed are always allowed. The other ASCII control characters, such as the form feed, are reported.

Consecutive disallowed characters in the same element are reported by a single diagnostic.

````c#
class Café // non-compliant: identifier
{
    // Résumé: non-compliant
    string Value = "é"; // non-compliant
    string Escaped = "\u00E9"; // compliant
    string Raw = """é"""; // compliant, raw strings are skipped by default
}
````

## How to fix violations

Replace the characters with their ASCII equivalent, or use an escape sequence (`\u00E9`, `\U0001F600`) in the strings and the character literals. The code fix replaces the characters with escape sequences in the regular strings, the UTF-8 strings, the character literals, and the text of the interpolated strings. Verbatim strings and raw strings do not support escape sequences, so the code fix is not available for them.

## Configuration

The printable ASCII characters are always allowed. You can allow more characters with a comma-separated list of code points or ranges of code points. The `U+` prefix is optional, and the invalid entries are ignored:

````
# .editorconfig file
MA0243.additional_allowed_ranges = U+00C0-U+00FF, U+20AC
````

Emoji are reported by default. You can allow them, including the sequences made of several code points such as the flags, the skin tones, and the sequences joined by a zero-width joiner:

````
# .editorconfig file
MA0243.allow_emoji = true
````

You can allow all the visible characters, so that only the invisible characters are reported. The invisible characters are the control characters, the format characters (zero-width characters, bidirectional control characters, ...), the spaces other than `U+0020` (non-breaking space, ...), the line and paragraph separators, the private-use and unassigned code points, the lone surrogates, the variation selectors, and a few blank characters such as `U+3164` (Hangul filler):

````
# .editorconfig file
MA0243.allow_visible_characters = true
````

You can skip some elements of the code:

````
# .editorconfig file

# Raw string literals: """text""", $"""text""", """text"""u8 (default: true)
MA0243.skip_raw_strings = true

# Regular strings: "text", "text"u8, $"text" (default: false)
MA0243.skip_strings = false

# Verbatim strings: @"text", @"text"u8, $@"text", @$"text" (default: false)
MA0243.skip_verbatim_strings = false

# Character literals: 'c' (default: false)
MA0243.skip_chars = false

# Comments: // and /* */ (default: false)
MA0243.skip_comments = false

# Documentation comments: /// and /** */ (default: false)
MA0243.skip_documentation_comments = false

# Identifiers (default: false)
MA0243.skip_identifiers = false
````

You can skip the whitespace characters that indent the lines. Only the whitespace characters located between the start of a line and its first non-whitespace character are skipped. The whitespace inside the string literals is never considered as indentation, as it can be part of the value:

````
# .editorconfig file
MA0243.skip_indentation = true
````

By default, the invisible characters are reported even in the skipped elements and even when they are part of `additional_allowed_ranges`, as they can be used to hide code. Only `skip_indentation` takes precedence. You can disable this behavior:

````
# .editorconfig file
MA0243.always_report_invisible_characters = false
````
