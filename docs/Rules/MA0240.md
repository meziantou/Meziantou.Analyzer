# MA0240 - Do not use banned syntax

## Description

The rule reports the syntax listed in a `BannedSyntaxes.txt` file, with the message given for it. This lets a project ban a language construct, such as `goto`, `lock`, primary constructors, or nested conditional expressions, and explain what to use instead, without writing a dedicated analyzer.

## Configuration

This rule is enabled by default, but it does nothing until a project has a banned syntax file, so it does not cost anything to the projects that do not use it.

To ban syntax, create a `BannedSyntaxes.txt` file in the folder of the project, or in one of its parent folders, such as the root of the repository to share it with all the projects. The `Meziantou.Analyzer` package adds the closest `BannedSyntaxes.txt` file to the additional files of the project, the same way MSBuild finds the closest `Directory.Build.props` file.

To stop the package from adding the file, set the `MeziantouIncludeBannedSyntaxesFile` property to `false` in a `Directory.Build.props` file. The package reads the property before the project file is evaluated, so setting it in the project file has no effect.

````xml
<Project>
  <PropertyGroup>
    <MeziantouIncludeBannedSyntaxesFile>false</MeziantouIncludeBannedSyntaxesFile>
  </PropertyGroup>
</Project>
````

The rule also reads the additional files named `BannedSyntaxes.txt` or `BannedSyntaxes.*.txt`, such as `BannedSyntaxes.Shared.txt`, that you add to the project, so a file shared by several projects can be combined with a file specific to a project:

````xml
<ItemGroup>
  <AdditionalFiles Include="BannedSyntaxes.Project.txt" />
</ItemGroup>
````

A file added both by the package and by the project is read once.

### File format

Each line contains a query, optionally followed by `;` and the message to report:

````text
# Lines starting with '#' are comments
GotoStatement; Use structured control flow instead
LockStatement
//ClassDeclaration/ParameterList; Do not use primary constructors
//ConditionalExpression//ConditionalExpression; Do not nest conditional expressions
//*[count(ParameterList/Parameter) > 5]/@Identifier; Use a parameter object instead of more than 5 parameters
````

- The query and the message are separated by the first `;` that is not in a string literal of the query.
- Empty lines and the lines starting with `#` are ignored.
- The message is optional. The diagnostic is `The syntax '<kind>' is banned: <message>`, or `The syntax '<kind>' is banned` without a message.

The query is either the name of a syntax kind or an XPath query.

### Syntax kinds

A query made of a single name, optionally preceded by `//`, is the name of a member of the [`Microsoft.CodeAnalysis.CSharp.SyntaxKind`](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.csharp.syntaxkind) enumeration, such as `GotoStatement`. The name is case-sensitive. The rule reports all the nodes of this kind. These queries are faster than the other XPath queries, as all the kinds are found in a single pass over the syntax tree.

Only the kinds of syntax nodes are supported, not the kinds of tokens or trivia. To find the kind of a construct, you can use:

- [`SyntaxKind.cs`](https://github.com/dotnet/roslyn/blob/main/src/Compilers/CSharp/Portable/Syntax/SyntaxKind.cs), the list of all the kinds in the Roslyn source code
- [Roslyn Quoter](https://roslynquoter.azurewebsites.net/), which shows the syntax factory calls that create a snippet, including the kind of each node
- [Razor Lab](https://lab.razor.fyi/#csharp), which shows the syntax tree of a C# snippet
- [SharpLab](https://sharplab.io) (Syntax Tree view)
- The Syntax Visualizer of Visual Studio

### XPath queries

The other queries are [XPath 1.0](https://www.w3.org/TR/xpath-10/) queries evaluated on each file, which is exposed as an XML document:

- Each syntax node is an element named after its kind, such as `ClassDeclaration` or `ParameterList`. The children of an element are the child nodes of the syntax node.
- The tokens of a node are the attributes of its element, named after the property of the node that returns them, such as `Identifier`, `Keyword`, or `Modifiers`. The value of an attribute is the text of the token. When the property returns several tokens, such as `Modifiers`, the value is the text of the tokens separated by a space. Missing tokens are not exposed.

The rule reports each element or attribute selected by the query. When the query selects an attribute, the diagnostic is reported on the tokens of the attribute. Use the `|` operator to select several constructs with the same message.

| Query | Reported syntax |
|-------|-----------------|
| `//ClassDeclaration/ParameterList` | The parameter list of the primary constructors of classes |
| `//ClassDeclaration[ParameterList]` | The classes that declare a primary constructor |
| `//ClassDeclaration/ParameterList \| //StructDeclaration/ParameterList` | The parameter list of the primary constructors of classes and structs |
| `//ConditionalExpression//ConditionalExpression` | The conditional expressions nested in another conditional expression |
| `//MethodDeclaration[@Identifier='Execute']` | The methods named `Execute` |
| `//MethodDeclaration/@Modifiers[contains(., 'async')]` | The modifiers of the `async` methods |
| `//ReturnStatement[ancestor::ConstructorDeclaration]` | The `return` statements in constructors |
| `//MethodDeclaration[count(ParameterList/Parameter) > 5]/@Identifier` | The name of the methods with more than 5 parameters |
| `//*[count(ParameterList/Parameter) > 5]/@Identifier` | The name of the methods, constructors, local functions, delegates, and types with a primary constructor that have more than 5 parameters |

Records use `ParameterList` for their positional parameters too, so `//RecordDeclaration/ParameterList` selects the positional parameters of records.

### Invalid entries

The lines of the file that are not valid, such as a name that is not a member of `SyntaxKind`, an invalid XPath query, or a query that does not return a node-set, are reported by [MA0241](MA0241.md). The other lines of the file are still applied.

## Example

With the following `BannedSyntaxes.txt` file:

````text
GotoStatement; Use structured control flow instead
//ClassDeclaration/ParameterList; Do not use primary constructors
````

````c#
class Sample(int value) // ❌ The syntax 'ParameterList' is banned: Do not use primary constructors
{
    void Test()
    {
        goto end; // ❌ The syntax 'GotoStatement' is banned: Use structured control flow instead

    end:
        return;
    }
}
````
