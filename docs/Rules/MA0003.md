# MA0003 - Add parameter name to improve readability
<!-- sources -->
Sources: [NamedParameterAnalyzer.cs](https://github.com/meziantou/Meziantou.Analyzer/blob/main/src/Meziantou.Analyzer/Rules/NamedParameterAnalyzer.cs), [NamedParameterFixer.cs](https://github.com/meziantou/Meziantou.Analyzer/blob/main/src/Meziantou.Analyzer.CodeFixers/Rules/NamedParameterFixer.cs)
<!-- sources -->

You should name the parameter when calling a method with a literal value:

- `null`
- `true`
- `false`
- `default`
- `"abc"`
- `42`

````csharp
obj.Test(null);

// Should be
obj.Test(name: null);
````

Some framework APIs are ignored by default when literals are expected by design, such as `Task.ConfigureAwait(...)`, `Volatile.Read(...)`, and `Volatile.Write(...)`.

# Configuration (`.editorconfig`)

````
[.*cs]
MA0003.minimum_method_parameters = 1 # Only consider methods with 1 or more parameters
MA0003.expression_kinds = Null, Boolean, Numeric, String, Default  # Default: Null | Boolean

# '|'-separated values of documentation comments https://github.com/dotnet/csharplang/blob/main/spec/documentation-comments.md#id-string-format
MA0003.excluded_methods = M:A.B(System.Int32) | M:C.D()

# The regex matches the documention comment of the method (https://github.com/dotnet/csharplang/blob/main/spec/documentation-comments.md#id-string-format)
MA0003.excluded_methods_regex = Sample.*Test

# Set to false to report the arguments whose name already matches the name of the parameter
MA0003.ignore_arguments_matching_parameter_name = true
````

If `MA0003.excluded_methods_regex` is not a valid regular expression, no method is excluded and [MA0220](MA0220.md) is reported. No method is excluded either if the evaluation of the regular expression times out.

You can annotate a parameter with `Meziantou.Analyzer.Annotations.RequireNamedArgumentAttribute`.
To use this attribute, add the `Meziantou.Analyzer.Annotations` NuGet package (or copy the attribute source into your project). See [Meziantou.Analyzer.Annotations README](https://github.com/meziantou/Meziantou.Analyzer/blob/main/src/Meziantou.Analyzer.Annotations/README.md).

```c#
Test("test"); // report a diagnostic as the parameter is not named

// Requires Meziantou.Analyzer.Annotations package
public void Test([RequireNamedArgument] string value) { }
```

The attribute is ignored on the receiver of an extension method (the `this` parameter), as it cannot be named when the method is called using the instance syntax (`value.Test()`).

# Arguments matching the name of the parameter

An argument is not reported when it is a local, a parameter, a property, or a field whose name matches the name of the parameter, ignoring the case. Naming such an argument doesn't improve readability:

````csharp
var sample = 0;
Test(sample); // no diagnostic, the argument already carries the name of the parameter

void Test([RequireNamedArgument] int sample) { }
````

For fields, the `_` and `s_` prefixes are also removed before comparing the names, as they are common naming conventions for instance and static fields:

````csharp
class Sample
{
    private int _value;
    private static int s_value;

    void A()
    {
        Test(_value);  // no diagnostic
        Test(s_value); // no diagnostic
    }

    static void Test([RequireNamedArgument] int value) { }
}
````

The prefixes are only removed for fields. A local named `_value` is still reported, as the prefix is not a convention for locals. The name of the parameter is also compared before removing the prefix, so a field named `_value` still matches a parameter named `_value`.

Set `MA0003.ignore_arguments_matching_parameter_name` to `false` to report those arguments.
