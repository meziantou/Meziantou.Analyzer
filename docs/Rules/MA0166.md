# MA0166 - Forward the TimeProvider to methods that take one
<!-- sources -->
Sources: [UseAnOverloadThatHasTimeProviderAnalyzer.cs](https://github.com/meziantou/Meziantou.Analyzer/blob/main/src/Meziantou.Analyzer/Rules/UseAnOverloadThatHasTimeProviderAnalyzer.cs), [UseAnOverloadThatHasTimeProviderFixer.cs](https://github.com/meziantou/Meziantou.Analyzer/blob/main/src/Meziantou.Analyzer.CodeFixers/Rules/UseAnOverloadThatHasTimeProviderFixer.cs)
<!-- sources -->

You should pass a `System.TimeProvider` when calling a method if there is an overload of the method that supports it.

````csharp
class Test
{
    public void A(System.TimeProvider timeProvider)
    {
        Task.Delay(default(TimeSpan)); // non-compliant
        Task.Delay(default(TimeSpan), timeProvider); // compliant
    }
}
````

Overloads without a `TimeProvider`, such as `Task.Delay(TimeSpan)`, use `TimeProvider.System`. When a `TimeProvider` is available, for instance because it is injected in the class, forwarding it ensures the code uses the same clock as the rest of the class, which lets the tests control the time with a fake `TimeProvider`.

This rule only reports a diagnostic when a `System.TimeProvider` is available in the scope. The instance members are not considered available in a static context, such as a static member or a field initializer. [MA0167](MA0167.md) detects the same cases, but reports them even if applying a fix would require you to change the calling method's signature.

## Configuration

````
# Include the overloads that are extension methods declared in a namespace that is not imported. The code fix adds the using directive. default: false
MA0166.include_extension_methods_from_not_imported_namespaces = false
````
